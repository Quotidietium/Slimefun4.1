## 测量方法说明（务必先读）

同一代码版本在不同 boot 之间，受 JIT 预热、GC 时机、OS 调度影响，**单次运行的方差可达 ±50%**（见下表 4.9.4 baseline 的 r1 与 r2：charge-write min 291 vs 210 ns）。

因此本报告以 **`min`（最小值）** 为主要判据——它反映 JIT 充分优化、无 GC/调度干扰时的代码路径下限，跨版本对比时最可信；`median` 仅作参考列。**只有当优化后 `min` 系统性、跨多轮地低于优化前，才认定为真实收益。**

## 全场景对比

各版本取两轮独立 boot。`min` 为主要指标。

### ① ticker-run（5000 个平凡 ticker 的完整调度周期）★ 核心成果

| 版本 | min (ms) | median (ms) | ns/块 (min) |
|---|---:|---:|---:|
| 4.9.3 | 2.74 | 3.01 | 602 |
| 4.9.4 优化前 r1 | 3.08 | 4.42 | 884 |
| 4.9.4 优化前 r2 | 3.28 | 3.43 | 686 |
| **4.9.4 优化后 r1** | **1.04** | 1.40 | 280 |
| **4.9.4 优化后 r2** | **1.20** | 1.31 | 261 |

**结论**：优化后 ticker-run `min` 由 ~3.1–3.3 ms 稳定降至 ~1.0–1.2 ms，两轮一致，**降幅约 −63%**；每 ticked 方块调度开销由 ~600–880 ns 降至 ~260–280 ns。信号远超噪声，是本批唯一在基准中清晰可量化的收益，来自 [profiler 改为按需收集](#优化清单)。

### ② BlockStorage charge-write（电网真实热路径，5000 块）

| 版本 | min (ns) | median (ns) |
|---|---:|---:|
| 4.9.3 | 183 | 191 |
| 4.9.4 优化前 r1/r2 | 291 / 210 | 363 / 219 |
| 4.9.4 优化后 r1/r2 | 200 / 194 | 215 / 206 |

**结论**：4.9.3→4.9.4 baseline 的差异（291 vs 210）纯属 boot 间噪声；优化后 `min` 稳定在 ~194–200 ns，与 4.9.3 持平或略低。P1+P2（setBlockInfo 跳过冗余 put + updateBlockInfo 轻量写入）的收益在此单点 bench 中被噪声淹没，但每写入省去一次 CHM volatile 写，在规模化电网下累积有效。

### ③ BlockStorage save（5000 个脏方块落盘）

| 版本 | min (ms) | median (ms) |
|---|---:|---:|
| 4.9.3 | 28.4 | 33.3 |
| 4.9.4 优化前 r1/r2 | 46.3 / 29.4 | 57.4 / 38.8 |
| 4.9.4 优化后 r1/r2 | 35.3 / 34.7 | 47.5 / 40.6 |

**结论**：低负载下（r2）4.9.4 已与 4.9.3 持平（~29 ms）；本批未改动 save 路径，数值波动属正常噪声。**save 无系统性回归**。

### ④ 空转机器配方扫描（1000 台 AContainer，每 tick）

| 变体 | 版本 | min (ns/tick) | median (ns/tick) |
|---|---|---:|---:|
| 空输入 | 4.9.3 | 404 | 761 |
| 空输入 | 4.9.4 优化前 r1/r2 | 643 / 653 | 794 / 875 |
| 空输入 | 4.9.4 优化后 r1/r2 | 726 / 585 | 978 / 666 |
| 不匹配输入 | 4.9.3 | 304 | 306 |
| 不匹配输入 | 4.9.4 优化前 r1/r2 | 457 / 614 | 501 / 662 |
| 不匹配输入 | 4.9.4 优化后 r1/r2 | 453 / 460 | 508 / 522 |

**结论**：空转机器已有负缓存（不匹配输入命中缓存即返回），本批未改动该路径。各轮 min 在 ~450–730 ns 间波动，属 boot 间噪声，**无系统性回归**。

### ⑤ 电容贴图更新（2000 个真实玩家头，同档位）

| 版本 | min (ns) | median (ns) |
|---|---:|---:|
| 4.9.3 | 163 | 166 |
| 4.9.4 优化前 r1/r2 | 162 / 175 | 170 / 188 |
| 4.9.4 优化后 r1/r2 | 185 / 170 | 198 / 177 |

**结论**：电容贴图四档去重在 4.9.3 已到位，本批未改动。数值噪声内，**无变化**。

### ⑥ 全息标签推送（2000 个，标签未变）

| 版本 | min (ns) | median (ns) |

## 优化清单

| 编号 | 提交 | 优化 | 基准可量化 |
|---|---|---|:---:|
| P3 | `e2809da20` | profiler 每块明细改按需收集（平时只记 tick 总耗时） | ✓ ticker −63% |
| P1 | `073871b2a` | `setBlockInfo` 写入同一 Config 时跳过冗余 put | 噪声内 |
| P2 | `073871b2a` | `EnergyNet` 结算复用 data + `updateBlockInfo` 轻量写入 | 噪声内（bench 不测电网结算） |
| P4 | `efa9a5bad` | `CargoNetworkTask.getOwner` 单 tick 缓存 | 噪声内（bench 不测 cargo） |
| P5 | `e2584ffea` | `TickerTask` 每区块只解析一次 BlockStorage | 噪声内 |

P1/P2/P4/P5 减少的是每 tick 每组件/节点的冗余 `ConcurrentHashMap` 查找或 `Bukkit.getOfflinePlayer` 调用，单点成本小、被 boot 间方差淹没，但逻辑上每 tick 减少 1–3 次映射操作，在生产规模化（数千 ticked 块 / 电网组件 / cargo 节点）下累积有效。

## 总体结论

1. **4.9.3 → 4.9.4 不存在 bench 覆盖路径上的系统性性能回归**。此前记录的 4.9.4 偏高值（charge-write 277 ns、save 43 ms、ticker 4.4 ms）是单次高负载 boot 的噪声；低负载复测后 4.9.4 baseline 已与 4.9.3 持平或更优。
2. **本批优化的核心成果是 tick 主循环 −63%**（profiler 按需收集），这是 bench 未覆盖、却影响每一个 ticked 方块的真实开销。
3. 其余 4 项为热路径去冗余，逻辑正确、测试全绿（1892/0/0/7），单点 bench 噪声内但规模化累积有效。
4. **唯一可观测行为变化**：profiler 平时不收集每块明细，仅 `/sf timings` 时收集；PlaceholderAPI `timings_lag` 占位符保持实时，DebugFish 查单块耗时需先 `/sf timings`。

## 与生产环境的差异（诚实声明）

- MockBukkit 的方块/实体操作成本与真实 Paper 服务端不一致，**倍数与相对趋势可信，绝对纳秒数仅供参考**。
- ticker-run 用平凡 ticker（仅测调度开销），真实机器 tick 还含 AContainer/EnergyNet 等逻辑，绝对耗时更高，但 profiler 优化的比例性成立。
- 未测量真实服务器端到端 TPS；生产级验证建议用 spark 在真实服务器对同一 ticker 场景做前后采样对比。
- 全量单元测试 1892 项通过、0 失败、0 错误、7 跳过。
