# SlimeFun4.1 v5.1.1

针对 v5.0.0 用户反馈的"太阳能发电机接入电路后不激活"问题的专项核查与修复。经端到端复现排查，当前代码的激活链路（放置 → 网络发现 → 分类 → 发电 → 结算充电）本身正确；本次修复了排查中实锤的一处坐标污染缺陷，并补上了此前缺失的激活链路端到端回归测试。

## 修复

- **全息偏移原地修改 `Block#getLocation()` 返回值（`HologramOwner`）**：`updateHologram`/`removeHologram` 直接对 `b.getLocation().add(offset)` 偏移——`Location#add` 是**原地修改**并返回自身，而 `getLocation()` 的契约并不保证返回防御性副本。能量调节器每个网络 tick 都会走该方法更新状态全息，逐次偏移使调节器坐标漂移（每次 +0.5/+0.75/+0.5），网络 regulator 身份随之失配：调节器 tick 解析不到自己的网络，真实网络被孤儿化——**后接入网络的新发电设备（如太阳能）永远不会被分类，表现为"接入电路不激活"**。真实 Bukkit 实现每次 `getLocation()` 返回新对象，故生产服多数场景侥幸无恙；本修复改为先 `clone()` 再偏移，行为确定、不受实现差异影响（每次全息更新多一次小对象分配，相对既有开销可忽略）
- 其余 15 处 `getLocation().add(...)` 用法（粒子/生成物视觉路径，均为一次性交互路径而非每 tick 身份路径）确认在真实 Bukkit 下无害，维持上游惯用写法不动

## 新增测试（端到端激活回归，5 场景）

`TestEnergyNetActivation`——用**真实的 EnergyRegulator BlockTicker** 驱动完整生产路径（此前测试只直驱私有结算方法，放置/发现/分类链路为零覆盖，是本次问题漏检的原因）：

1. 太阳能 + 电缆 + 调节器 + 消费者：发电机入网分类、消费者实际充电
2. 反序放置（先发电机后调节器）：同样激活
3. **网络先建、太阳能后接入**（BlockPlace → updateAllNetworks → markDirty 路径，即用户报告场景）：正常激活（修复前该场景失败）
4. 跨区块边界接入（空间 chunk 索引正确性）：正常激活
5. 电容 + 双消费者：电容入网分类、能量正常分配

## 核查结论（未发现其他激活缺陷）

- 放置链路事件次序正确：block info 写入（HIGHEST）先于 NetworkListener（MONITOR），`hasBlockInfo` 门控不会漏触发 markDirty
- 空间 chunk 索引为超集过滤器，候选网络一律经 `connectsTo` 值确认，跨区块接入无死角（场景 4 实测）
- 双网络并入/调节器身份解析/仲裁、断缆重建、异常发电机隔离（unpooledGenerators）等 5.0.0 新逻辑逐路径复核，均为自愈式正确行为
- 事件 async 声明（NetworkCreate/Dispose、EnergyGenerate/Consume/NetTick）均为自适应构造，异步 ticker 触发不会抛 IllegalStateException
