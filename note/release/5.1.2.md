## 数据完整性修复（5 项）

- **菜单并发丢更新（实证）**：`DirtyChestMenu.pushItem/consumeItem` 的读-改-写无同步——8 线程探针 200 轮实测 3 轮静默消失共 11 物品；加菜单监视器后 0/200。机器异步 ticker 与主线程（cargo/玩家）操作同一机器菜单的窗口闭合
- **菜单合并分支持久化缺失**：原地 `setAmount` 从不置脏，"只推产出不消耗输入"的机器（GEO 采矿机/收割机器人等）产出并入半栈后永不落盘，重启丢物品
- **BlockMenu.dropItems 读-清竞态**：窗口内异步推入的物品被清槽静默虚空
- **UniversalBlockMenu 异步关闭观看者**：异步 ticker 删除队列直接在异步线程 `closeInventory()`（异步实体状态 + 错误线程触发关闭事件使 menus 表跨线程访问）；改经 runSync + 表换 ConcurrentHashMap
- **内置研究 id 173 重复（上游既有，HIGH）**：煤发电机与生物反应器共用持久化键 `researches.173`——解锁其一即双双解锁；重编号 + 老存档双恢复兼容 + 重复 id 启动告警

## API 可用性修复（1 项，HIGH）

- **ResearchBuilder 默认遗留 id=0**：与内置首个研究及其它默认 id 附属研究在持久化键上互相污染（解锁其一即全部误解锁）；改为从 NamespacedKey 确定性派生（跨重启稳定、避开内置密集段）
