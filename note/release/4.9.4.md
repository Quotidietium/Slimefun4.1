# SlimeFun4.1 v4.9.4(Release Preview)

本版本聚焦代码安全性与高负载稳定性加固，并在此基础上去除 tick 主循环与高频热路径的冗余开销（profiler 改为按需收集、charge 写入与电网/cargo 结算去冗余查找）。全面排查并修复了领地保护绕过、刷物品/少消耗、并发竞态与内存泄漏、电路网络崩溃等问题。无公开 API 变更、无磁盘存储格式变更（全部改动为内部实现或附加性方法）。

## 安全（领地保护绕过）
- **可编程机器人**：Butcher Android 攻击实体、Farmer Android 收获作物、可编程机器人移动此前均未调用 ProtectionManager，可越过领地边界击杀他人牲畜、偷取作物、闯入他人领地。现统一在 attack/farm/move 入口按机器人所有者校验 ATTACK_ENTITY / BREAK_BLOCK / PLACE_BLOCK，与 Miner/Woodcutter Android 既有校验一致；getOwner 上移至 ProgrammableAndroid 复用
- **Cargo 物流网络**：cargo 输入节点抽取、输出节点注入容器前，现按节点所有者校验目标容器的 INTERACT_BLOCK 权限。此前 cargo 仅按物理拓扑+频率传输，可在两领地相邻处用贴墙节点抽走/塞入他人物品栏。校验为 per-node per-cargo-tick（O(节点数)），不影响既有 cargo 性能优化；ownerless(遗留/损坏)节点沿用宽松策略
- **Ancient Altar**：仪式消耗 8 个 pedestal 上的物品，此前仅校验祭坛本体，现逐一校验每个 pedestal 的 INTERACT_BLOCK 权限，杜绝借他人领地内 pedestal 祭品完成配方
- **BlockPlacer**：owner 数据缺失（遗留/损坏方块）时此前绕过一切领地保护。owner-tracking 在放置时即写入，ownerless 仅属遗留方块；现改为拒绝放置（安全失败模式，不越权放置），闭合绕过

## 稳定性（数据完整性 / 高负载）
- **玩家档案(PlayerProfile)**：PlayerData 的研究/背包/路径点集合改为并发实现，消除异步自动保存线程迭代时主线程并发修改导致的 ConcurrentModificationException；引入修改纪元(modificationEpoch)，保存仅在纪元未变时清除 dirty，杜绝保存期间并发改动因 dirty 被误清而丢失；dirty/markedForDeletion 改 volatile 修复跨线程可见性；setResearched 调整为「先改数据后标记 dirty」
- **ItemFilter**：库存尺寸不足的误配分支此前不清 dirty，导致每 tick 重复 update() 并逐槽放大 warn 日志；现按永久误配处理
- **EnergyNetComponent.addCharge**：改用 flowSafeAddition，防止大容量+大充能时 int 溢出写出负值
- **EnergyNet.tick**：super.tick() 可能因拓扑变更注销本网络，注销后不再继续结算，避免短暂双充/双供
- **BlockStorage**：loadBlocks/loadInventories 的 4 处 listFiles() 改用 listFilesOrEmpty 守护，目录缺失不再 NPE 中断整个世界的加载
- **BackupService**：purgeBackups 此前删除方向错误（删较新而非最旧），导致旧备份永不清理、近期备份被误删；改为删除最旧的尾部、保留最新 N 个。run() 的 catch 改为 Exception（杂散文件名解析异常不再逃逸到 onDisable 跳过 setInstance），createBackup/addDirectory 的 listFiles() 加判空，purgeBackups 过滤不符合格式的文件

## 正确性（刷物品 / 少消耗 / 物品吞没）
- **AContainer**：异步 tick 与主线程点击操作同一库存，配方按快照匹配后再消费的窗口内可被移走输入导致免费产物。现消费前先逐槽重新校验 live 槽位类型与数量，任一不符则整批中止（不消费、不启动、不缓存负命中）
- **AbstractSmeltery.canCraft**：原仅按类型匹配且不跟踪槽位用量，重复输入或数量不足的配方被放行后少消耗。现按每槽剩余量严格校验每个输入的类型与数量
- **OreWasher**：非 legacy 模式多余的 STONE_CHUNK 此前被静默吞没，现补偿掉落
- **CargoNet.mapOutputNodes**：补齐与 mapInputNodes 一致的 0-15 频率范围校验，避免越界频率输出节点被静默永久禁用
- **AbstractAutoCrafter**：合成后 leftover（空桶/空瓶）addItem 失败此前被静默吞没；现通过容器 holder 位置补偿掉落（不改 public craft() 签名）

## 并发竞态 / 内存泄漏
- **SoulboundListener**：玩家死亡后在重生前下线/被踢，PlayerRespawnEvent 不触发，灵魂绑定物品滞留内存并丢失。新增 onQuit 处理：下线时归还物品随存档保存（map 排空后复活为 no-op，不重复）
- **SlimefunBowListener**：未命中即消失的箭(过期/进入未加载区块//kill)永不触发 ProjectileHitEvent，projectiles 表缓慢无界增长。新增每 30s 周期清理无效实体条目
- **TickerTask.reportErrors**：bugs 计数改用 ConcurrentHashMap.merge 原子自增，修复异步 ticker 与主线程同步 tick 双路径下的丢失更新与重复 ErrorReport
- **SlimefunRegistry**：globalItemHandlers 与 mobDrops 改为 ConcurrentHashMap（与 profiles/worlds/chunks 等并发表一致），RecipeType.registerMobDrop 改用 computeIfAbsent，消除后置注册场景下的非原子复合操作
- **电容贴图缓存**：capacitorTextureStages 按历史电容位置无界增长。新增 clearStaleCapacitorTextures()，每 5 分钟异步剔除已不存在方块的条目，使缓存只追踪现存电容

## 深入审计（第二轮：机器功能 / 数据损坏 / 输入解析）

### CRITICAL — 9 台自定义配方机器永久空转
- **AContainer.findNextRecipeCached 绕过子类 findNextRecipe 覆写**：本 fork 早期性能 commit 让 tick 直接调用私有 scanForRecipe 而非可覆写的 findNextRecipe，导致 OilPump / ElectricGoldPan / AutoBrewer / AutoEnchanter / AutoDisenchanter / AutoAnvil / BookBinder / ElectricDustWasher / ProduceCollector（空 recipes + 自定义 findNextRecipe）完全不工作。现对空 recipes 的机器改走 findNextRecipe，恢复虚方法分派

### Medium — 数据损坏销毁机器
- **Reactor.generateEnergy / ExpCollector.getStoredExperience / ResourceManager.getSupplies** 对 BlockStorage/区块数据裸 parseInt，数据损坏（崩溃写入/手工编辑/磁盘错误）会抛 NumberFormatException，TickerTask 累计 4 tick 后销毁机器并掉落燃料/副产物。现加 try-catch，损坏当作 0/空，与 EnergyNetComponent.getCharge 加固策略一致

### High — 多方块少消耗
- **Compressor / OreCrusher / PressureChamber** 用 isItemSimilar（不校验数量）匹配配方且 removeItem 忽略返回值，不足量也匹配导致少消耗（1 煤炭块→9 碳等）。现先校验 item.getAmount() >= recipeInput.getAmount()

### Low — 输入解析与边界
- **NumberUtils.getInt / GiveCommand / BackpackCommand / PlayerProfile.getBackpack**：NUMERIC 正则([0-9]+)能匹配超长串，其后 parseInt 仍会溢出。统一加 try-catch
- **StatusEffect**：PDC 值损坏（无分号→越界、非数字）改为安全返回 false/empty
- **Debug.formatMessage**：占位数多于 vars 或消息以 '{' 结尾时不再越界
- **HashedArmorpiece**：hash/item 字段改 volatile，修复异步盔甲任务跨线程可见性

## 第三轮：闭合所有剩余保护缺口（owner-tracking 推广至更多机器）
- **Reactor ↔ ReactorAccessPort**：为两者新增 owner-tracking（onPlace 记录 owner），getAccessPort/getReactor 用 SlimefunUtils.isSameOwner 校验，杜绝在他人反应堆上/下方放置端口跨领地喂燃料/取副产物/查看反应堆（含 GUI「view」按钮）
- **GiveCommand / ResearchCommand**：非玩家放行由「!(sender instanceof Player)」改为「sender instanceof ConsoleCommandSender」，命令方块不再绕过 cheat 权限（与 StatsCommand 一致）
- **可编程机器人 INTERFACE**：depositItems/refuel 访问对端 ANDROID_INTERFACE dispenser 前校验 owner 的 INTERACT_BLOCK，杜绝贴边境偷燃料/塞物
- **ExpCollector / ProduceCollector / AutoBreeder / AnimalGrowthAccelerator / InfusedHopper**：范围内影响实体/吸取物品前按机器 owner 校验 INTERACT_ENTITY/INTERACT_BLOCK，杜绝跨境吸经验/挤奶/触发繁殖/催熟/吸掉落物；为无 owner-tracking 的机器加 SlimefunUtils.ownerTrackingPlaceHandler() 记录 owner
- **NetherStarReactor**：凋灵效果现按反应堆 owner 校验（玩家 ATTACK_PLAYER、生物 ATTACK_ENTITY），不跨境凋灵
- **SlimefunUtils** 新增 getOwner(Location) 与 ownerTrackingPlaceHandler() 复用工具
- 全量 getNearbyEntities 自查：剩余均为玩家触发且经可取消的 EntityDamageByEntityEvent（StomperBoots/ExplosiveBow）或良性（TelepositionScroll 旋转、Rune 修改自有掉落物），非保护缺口

## 已知未修复（权衡 / 边缘，非保护缺口）
- **BackpackCommand / TeleporterCommand 的 getOfflinePlayer(String)**：对从未上线的玩家名可能触发同步 Mojang 查询（阻塞主线程）；受权限门控，属轻度 DoS 面（性能而非保护缺口），暂保留

## 性能优化（tick 主循环与高频热路径去冗余）

经跨两轮 MockBukkit 基准复测确认：4.9.4 相对 4.9.3 在 bench 覆盖路径上无系统性大回归（charge-write / save / ticker 的 min 值在低负载下已追平或超过 4.9.3；此前记录的偏高值属机器高负载噪声）。本批优化聚焦 bench 未充分覆盖的 tick 主循环与高频热路径，全部为内部实现优化，无公开 API 变更、无磁盘存储格式变更：

- **SlimefunProfiler 改为按需收集每块明细**：此前每个 tick 都对所有 ticked 方块全量收集计时（每块 2 次 nanoTime + 对象分配 + CHM 合并 + queued CAS），而本 fork 移除 bStats 上报后这些数据仅供诊断（PlaceholderAPI 占位符、DebugFish、/sf timings），绝大多数服务器无人查看。现仅在 `/sf timings` 请求时才收集每块明细，平时只记录 tick 总耗时。基准 ticker-run（5000 平凡 ticker）min 由 ~2.5–3.3 ms 降至 ~1.0 ms（约 **−60%**）。PlaceholderAPI timings 占位符保持实时不变；DebugFish 查单块耗时需先 `/sf timings` 开启收集
- **tick 主循环去冗余查找**：`BlockStorage.setBlockInfo` 写入同一 Config 引用时跳过冗余 put；`TickerTask` 每区块只解析一次 BlockStorage 传入 tickLocation，跳过每块的 world 查找
- **电网结算 charge 写入去冗余**：`EnergyNet` 结算循环每组件仅取一次 LocationInfo 复用于读与写；新增 `EnergyNetComponent.setCharge(Location, Config, int)` 与 `BlockStorage.updateBlockInfo` 轻量写入路径，省去 setCharge 内 getCharge 重查与 addBlockInfo 内重复定位
- **cargo 领地校验 owner 解析单 tick 缓存**：`CargoNetworkTask.getOwner` 对同一节点（尤其被多输入节点共享的输出节点）每 cargo-tick 重复解析 owner（读 BlockStorage + `Bukkit.getOfflinePlayer`），现以 task 实例级缓存去重，降低 4.9.4 为闭合领地绕过而新增的每节点校验开销

## 兼容性
- 无公开 API 变更、无磁盘存储格式变更、无机器行为变更（cargo/altar/机器人受领地限制属正确的安全行为收敛）
- 全量测试 1892 项通过、0 失败（CRITICAL 的 9 台机器端到端回归测试因 MockBukkit 放置接口对自定义 AContainer 的限制未能落地，该项修复已由逐机代码审查 + 全量套件验证）
