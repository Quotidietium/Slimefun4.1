# SlimeFun4.1 v5.0.0

在 v4.9.5（tick 热路径性能优化）基础上，完成大规模**公开 API 扩展**：面向附属插件新增约 200 个公开事件、3 项非事件 API，并对 6 个既有事件追加可修改能力。全部为**纯增量改动**——未删除或修改任何既有公开 API 签名，无磁盘存储格式变更，无机器行为变更（未注册监听器时行为与 v4.9.5 完全一致）。

## 事件 API（约 200 个新增事件）

统一设计约定：事件均在动作发生前触发、可取消（取消即否决该动作，物品/状态保持原样）；多数事件暴露 `setXxx` 方法，允许附属插件**就地修改**本次动作的产物、消耗、时长、落点、方向等，修改只作用于当次操作，不污染共享定义。事件覆盖的领域：

- **机器与电力**：`AsyncMachineOperationStartEvent`、`MachineRecipeStartEvent`（可改操作时长）、`AutoCrafterCraft(Event|CompleteEvent)`、`AutoAnvilRepairEvent`、`AutoBrewEvent`、`AsyncAutoDisenchanterProcessEvent`、`AsyncAutoEnchantmentSelectEvent`（逐项改附魔选择）、`ComposterProcessEvent`、`DustWashProcessEvent`、`ElectricGoldPanProcessEvent`、`ProduceCollectorCollectEvent`、`ExpCollector(Collect|Produce)Event`、`CrucibleLiquidGenerateEvent`、`IgnitionChamberUseEvent`、`EnhancedFurnace(Burn|Smelt)Event`、`SmelteryFireConsumeEvent`、`GeneratorProduceByproductEvent`、`Reactor(FuelBurn|CoolantConsume|ProduceByproduct|ModeChange)Event`、`NetherStarReactorWitherEvent` 等
- **能源网络**：`EnergyGenerateEvent`、`EnergyConsumeEvent`（可改/取消单个消费者充能量）、`EnergyNetTickEvent`、`SolarHelmetChargeEvent`、`ChargingBenchChargeEvent`

- **可编程/工业机器人**：`Android(Attack|Mine|Fish|Move|Rotate|Refuel|FuelConsume|ItemDeposit|ScriptChange|ChopTree)Event`、`ButcherAndroidKillEvent`（可改经验产量）、`IndustrialMiner(Start|Stop|Mine)Event`、`GEOMining(Start|Complete)Event`、`GEOScanEvent`、`OilPumpExtractEvent`（可改油耗）、`FluidPumpCollectEvent`

## 非事件 API

- **研究前置依赖系统**：`Research#addDependency(Research)` 支持声明研究前置，未解锁前置时研究不可解锁（配套 `ResearchLockEvent` 可观测/拦截）；该检查在 `PlayerResearchTask` 统一强制——指南、知识典籍分享、`/sf research all` 与 `research.unlock()` API 均不可绕过（`/sf research all` 已按依赖序多趟解锁）
- **`ResearchBuilder` 流式构建器**：链式声明 key/name/cost/绑定物品/前置依赖，`build()` 或 `register()` 一步完成（既有 `Research` 构造器完全保留）
- **标记接口 `SlimefunWeapon` / `SlimefunFood`**（`core.attributes`）：无行为标记，附属可通过 `instanceof` 识别武器/食物；内置武器（SlimefunBow、VampireBlade、SeismicAxe、SwordOfBeheading 等）已实现 `SlimefunWeapon`

## 既有事件增强（6 个）

`AndroidMineEvent`（新增 getDrops 可改开采掉落）、`BlockPlacerPlaceEvent`（setItemStack 接线生效）、`PlayerLanguageChangeEvent`（可取消 + setNewLanguage）、`RadiationDamageEvent`（setExposure 可改有效辐射等级）、`ResearchUnlockEvent`（可改研究时长）、`TalismanActivateEvent`。均为附加性方法，签名兼容。

## 兼容性

- 无既有公开 API 删除或签名变更、无磁盘存储格式变更、无机器行为变更
- 全部事件在未注册监听器时走原代码路径（多数事件触发点带监听器存在性短路，零开销）
- 既有附属插件无需任何改动
- **附属开发者注意**：部分事件触发于异步线程（机器/网络 ticker、盔甲任务、辐射任务等），其 `isAsynchronous()` 返回 `true`——监听这些事件的附属代码同样运行在异步线程，请勿在监听器中直接操作 Bukkit 世界状态，需要时应调度同步任务；各事件 Javadoc 已注明其线程上下文

## 深度审计续（第 17→35 轮，详见 note/audit/5.0.0-audit.md）

在上述 16 轮审计基础上，又进行了 19 轮专项深审（子系统逐个 + bug 类全量清扫），新增 **23 项功能修复**（含 4 HIGH 默认作弊/数据丢失 + 2 HIGH bug 类共 16 台机器）：

- **输入欠付作弊（HIGH，4 台机器）**：Composter/Crucible 的 `isItemSimilar` 不查 amount + `removeItem` 部分移除 + 完整产出 → 1 叶→1 泥土（应 8:1）、1 沙→1 盐（应 2:1）；OreWasher SALT 同型；GrindStone/Juicer 同型守卫统一。修复：`hasEnoughInput(containsAtLeast)` 在事件前校验库存足量
